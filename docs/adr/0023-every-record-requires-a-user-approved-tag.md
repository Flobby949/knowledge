# 每条记录至少具有一个“我的标签”

每条尚未永久删除的 Record 在任一成功事务结束时，必须至少具有一个 `assigned_by = USER`、目标为该 Record、状态为 `ACTIVE` 且所指 Tag 为 `USER_APPROVED` 的 Tag Assignment。知识点级 AI Assignment、尚未认可的 AI 候选和已屏蔽关联都不满足该不变量；系统也不自动补建“未分类”标签。

新建记录必须选择已有“我的标签”、新建标签，或把同名 AI 候选“升级并使用”。编辑器允许用户在未提交状态下暂时移除最后一个标签，但此时保存禁用；用户重新选择或新建至少一个标签后才能提交。服务端不依赖客户端校验：创建记录和更新记录级标签都接收最终标签集合，在同一事务中校验非空并原子写入，避免通过多请求替换标签时短暂持久化无标签记录。

只修改标签关联仍不创建 Fragment Revision，也不触发 AI 整理；原文变化时才按用户选择产生新版本和后续处理。完整恢复在写入前验证每条记录满足同一不变量，任一记录无有效“我的标签”时整包拒绝且不留下部分数据。永久删除记录不受最少标签校验阻塞。

该决定增加了快速记录前的最小分类成本，但确保首页标签场、标签筛选和后续知识网络始终有真实的用户认可入口，避免系统虚构默认标签或让无标签记录长期脱离可视结构。它也把新增约束放在尚无历史数据的阶段，避免未来为既有无标签记录补迁移规则。
